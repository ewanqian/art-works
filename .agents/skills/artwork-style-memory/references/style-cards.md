# Artworks Style Cards · public-safe working library

> Dated 2026-11-09. These are **retrieval cues and artistic distinctions**, not automatic presets, final approved visual styles or public proof of technical source. Full original node parameters and exclusive material assets remain private.

## DF-01 · Drop Flow / State-carried temporal flow

**Evidence:** artist-recalled + source-observed. Lifetime subchain `MECHANISM_TESTED`; whole visual and GPU simulation **not approved**.

- **Keep:** point birth + frame-to-frame geometric state, accumulated motion, meaningful survival/deletion, densities and directed continuous movement. Motion should feel like it contains previous moments, not a fresh randomized particle reset at every frame.
- **Flexible:** author-selected camera, lighting, slice/window, intensity/scale, sampled audio curve and eventual live control.
- **Not this:** a sin/noise fake envelope masquerading as an original music track; generic attractor or spring model; alpha trails that merely hide an arbitrary respawn; claiming 6 State sockets are 6 animated particle fields.
- **Check:** an original matched audio slice over several consecutive frames; source birth/topology, density-by-region, remaining life distribution and visual cadence.
- **Why keep:** the author's complaint about old Processing/GPU imitations was **different motion relations**, not insufficient particle count.

## KA-01 · KASHIWA Amb vs Ice / musical branches of one system

**Evidence:** artist-recalled. Each track's actual Blender node graph and audio Bake source still needs verification.

- **Amb:** fluid, comparatively romantic, expressive continuity; avoid forcing every beat into a large transient.
- **Ice:** unexpectedly precise-feeling rhythmic alignment and strong dynamic articulation. The author liked the music-driven intensity, but **beat detector is not established**.
- **Shared method:** duplicate and transform a proven underlying system into differentiated musical behaviours; the track's emotion, light/camera and musical input can change without inventing a new source simulator.
- **Not this:** every track rebranded as the same Drop Flow preset; “Ice uses true kick detection” without original source proof.
- **Check:** paired excerpt/frames from each track, tempo and source control; author identifies emotional contrast without relying on file names.

## MR-01 · ENTROPY → REACTOR / structural wire reveal

**Evidence:** author-recalled + existing historical project brief. Precise selected-source shader/lighting chain **unverified**.

- **Keep:** coherent machine hierarchy and topology. Lines appear and describe something *real in the 3D model*, resolving into a readable complex structure rather than a random network.
- **Temporal phrase:** acquire → partial reveal → geometric identity → highlighted scan/lock → slow inspect/rotate. The structure can remain still while selective light provides time.
- **Flexible:** Blender Mesh/Curve/Shader/Emission methods, camera angle, dramatic underlight/rim, spatial accents, restrained annotation or post noise.
- **Not this:** overlay a fake HUD with invented sensor measurements, arbitrary rings, loud full-field strobing or claiming a visually plausible tokamak model is engineering accurate.
- **Check:** reveal sequence recorded from actual final source scene, with same mesh and angle; compare clarity of structure and high-value lighting to earlier Entropy version. Confirm author-selected material and render.

## NF-01 · No Further Input Required / autonomous rule vs human observation

**Evidence:** artist-recalled; source variant and human screen-recording verification pending.

- **Keep:** a clean constrained generative rule operating independently, juxtaposed with the human manipulation/viewing process; nuanced variations can emerge from changed polygon sides, view, overlap, and cursor-driven exploration.
- **Time:** contrast a seemingly repetitive autonomous evolution with deliberately searched and selected observation moments.
- **Flexible:** polygonal structures, camera/orientation, persistence of original trace, authored edit/recording selection.
- **Not this:** presenting captured mouse interventions as autonomous AI learning, adding decorative complexity or replacing the duality with a single attractor preset.
- **Check:** original generated loop and a separate author's captured operation. Name which images require human intervention.

## EP-01 · SRE / Entropy terminal as a compositional spatial field

**Evidence:** author-recalled + existing project archives. Which planned visuals shipped must be confirmed from performance recordings.

- **Keep:** intentional large-scale information architecture, screen boundaries, real mechanical/satellite topology, orchestration of line/point/label density, modular performance states, and negative space.
- **Flexible:** screen-specific camera, model reveal, large data fields, authored state phrases and controlled beats.
- **Not this:** crowded unreadable pseudo-technical text, generic science dashboard, charts with fake measurements, or treating ten configured states as proof of ten stage-used cues.
- **Check:** actually-used final venue footage and per-screen system output, readability at audience viewing distance, author selected compositions.

## Style card lifecycle

`PROVISIONAL / ARTIST_RECALLED → SOURCE_GROUNDED → TESTED_CAPTURE → ARTIST_SELECTED → REUSABLE`

These stages track **specific techniques or variations**, not a whole artwork's exhibition status. Candidate cards do not create a new work or override collective authorship. Keep provenance, project identity, source rights and author feedback attached to the card.
